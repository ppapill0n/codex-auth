# codex-auth

## 설명

`codex-auth`는 하나의 Linux 사용자 계정에서 여러 Codex 계정을 **번갈아 사용**하기 위한 작은 도구입니다.
`~/.codex`는 하나만 유지하고, 계정별로 보관한 `auth.json`을 복사해 현재 인증을 교체합니다.
설정, 대화 기록, 스킬, 플러그인은 공통으로 사용합니다.
현재 계정은 `codex-auth save`로 저장합니다. 저장 이름은 이메일의 `@` 앞부분에서 자동으로 정합니다.

```text
~/.auth/
  alice.json ── switch alice ──▶ ~/.codex/auth.json
  bob.json   ◀── save ───────── ~/.codex/auth.json  # bob@example.com으로 로그인한 경우
  .current   # 현재 선택 이름 하나만 저장

~/.codex/
  config.toml
  sessions/
  skills/
  ...
```

한 번에 한 Codex 계정만 사용하며, 계정 전환 전에 기존 Codex 실행을 마치는 방식을 전제로 합니다.
`switch <이름>`과 `logout`은 같은 Linux UID의 Codex 프로세스가 남아 있으면 중단합니다.
`status`와 `cleanup`으로 남은 프로세스를 확인하고 정리할 수 있습니다.
계정 전환 시 현재 인증을 해당 계정의 저장본에 먼저 반영해 갱신된 토큰을 보관합니다.
`logout`은 자동 저장 없이 현재 인증을 지웁니다.

## 명령어 소개

### 설치: `init`

필요 환경은 **Linux, Python 3.11 이상, 기존 Codex CLI 설치**입니다.
프로세스 종료에는 Linux pidfd 지원이 필요합니다. 추가 Python 패키지는 사용하지 않습니다.

이 프로젝트를 보관할 디렉터리에서 일반 사용자 권한으로 실행하세요.

```bash
chmod +x ./codex-auth
./codex-auth init
```

`init`은 `~/.auth`를 만들고 `~/.local/bin/codex-auth`를 현재 스크립트로 연결합니다.
`~/.local/bin`이 PATH에 있으면 이후 어느 디렉터리에서든 `codex-auth`를 실행할 수 있습니다.
PATH에 없는 경우 다음 설정을 셸 시작 파일(`~/.bashrc`, `~/.zshrc` 등)에 추가하고 새 터미널을 여세요.

```bash
export PATH="$HOME/.local/bin:$PATH"
```

### 명령 목록

| 명령 | 동작 |
| --- | --- |
| `codex-auth init` | 인증 보관 디렉터리 생성 및 명령 설치 |
| `codex-auth save` | 현재 인증을 저장. 이메일의 `@` 앞부분을 저장 이름으로 자동 사용 |
| `codex-auth save --force` | 자동으로 정한 이름의 기존 저장본 덮어쓰기 |
| `codex-auth list` | 저장된 이름 목록 출력 |
| `codex-auth switch` | 저장 계정 목록과 현재 계정을 `→`로 표시 |
| `codex-auth switch <이름>` | 현재 인증을 기존 저장본에 자동 저장한 뒤 선택한 계정으로 전환 |
| `codex-auth logout` | 자동 저장 없이 현재 `auth.json` 제거 |
| `codex-auth status` | 현재 Linux UID의 Codex 프로세스 조회 |
| `codex-auth cleanup` | 종료 없이 프로세스 목록과 사용법 출력 |
| `codex-auth cleanup <PID> [PID ...]` | 지정한 Codex 프로세스 종료 |
| `codex-auth cleanup all` | 현재 Linux UID의 Codex 프로세스를 일괄 종료 |
| `codex-auth cleanup <PID 또는 all> --force` | 정상 종료 요청 후에도 남은 대상 강제 종료 |
| `codex-auth <명령> --help` | 명령별 도움말 |

`--force`는 `-f`로도 쓸 수 있습니다. `cleanup all`의 `all`은 PID와 섞어서 지정할 수 없습니다.
저장 이름을 직접 정하고 싶을 때만 선택적으로 `codex-auth save <이름>`을 사용하세요.
직접 정한 이름의 저장본을 갱신할 때는 `codex-auth save <이름> --force`로 같은 이름을 지정합니다.
이전 명령 이름인 `login`, `store`는 각각 `switch`, `save`로 변경되었습니다.

### 사용 예시

첫 계정 저장은 이름 인자 없이 실행합니다.

```bash
codex login
codex-auth save
```

예를 들어 `alice@example.com`으로 로그인했다면 `~/.auth/alice.json`에 저장됩니다.

다른 계정(예: `bob@example.com`) 등록:

```bash
# 기존 Codex 작업을 마친 뒤 일반 터미널에서 실행
codex-auth save --force        # 보관할 현재 인증을 먼저 저장
codex-auth logout              # 자동 저장하지 않음
codex login
codex-auth save
```

저장된 계정으로 전환:

```bash
# 기존 Codex 작업을 마친 뒤 일반 터미널에서 실행
codex-auth status
codex-auth cleanup all          # 남은 Codex 프로세스가 있을 때
codex-auth switch               # 목록과 현재 계정 확인
codex-auth switch bob
codex resume                    # 또는 codex
```

예를 들어 현재 계정이 `alice`라면 목록은 다음과 같습니다.

```text
→ alice
  bob
```

`cleanup all`은 **작업 중인 세션과 daemon도 종료 대상에 포함**합니다.
종료할 프로세스가 일부라면 `cleanup <PID>`를 사용하세요.
`codex-auth switch <이름>`은 파일을 교체하며 Codex를 실행하지 않습니다.
새 인증을 받는 `codex login`과 구분해서 사용하세요.

## 디테일

### 인증 파일과 저장 이름

보관 위치는 현재 사용자의 `~/.auth/<이름>.json`, 적용 위치는 `~/.codex/auth.json`입니다.
`codex-auth save`는 기본적으로 이메일에서 저장 이름을 자동으로 정합니다.
이를 위해 `tokens.id_token`의 JWT payload를 로컬에서 디코딩합니다.
이메일이 없으면 `tokens.access_token`에서도 찾으며, 지원하는 claim은 `email`과
`https://api.openai.com/profile.email`입니다.
JWT 디코딩은 이름 추정과 로컬 계정 비교에만 사용하며 서명이나 인증 유효성을 검증하지 않습니다.

이메일의 `@` 앞부분을 그대로 사용하며 `+`도 보존합니다.
이름 인자는 선택사항입니다. 다른 이름을 쓰고 싶으면 `codex-auth save work`처럼 지정할 수 있습니다.
API 키 인증처럼 이메일이 없거나 안전한 파일 이름을 만들 수 없는 경우에는 이름을 직접 지정해야 합니다.
이름은 영문/숫자로 시작하는 1~64자의 영문·숫자·`_`·`-`·`.`·`+`를 허용합니다.
경로나 숨김 파일 이름은 받지 않습니다.

명령 인자의 `alice`와 `alice.json`은 같은 파일을 뜻합니다.
이메일 앞부분 자체가 `alice.json`이면 `alice.json.json`으로 저장됩니다.
도메인이 달라도 이메일 앞부분이 같으면 이름이 충돌합니다.
중복 저장은 기본 거부하며 `--force`를 명시해야 덮어씁니다.
`save`가 성공하면 저장한 이름을 현재 선택으로 기록합니다.

### 현재 계정 표시와 직접 로그인 감지

`~/.auth/.current`에는 현재 선택 이름 하나만 기록합니다. 전환 이력이나 별도 계정 DB는 만들지 않습니다.
`switch`는 이 이름을 그대로 믿지 않고 실제 `auth.json`을 저장본들과 비교합니다.
조회만 할 때는 파일을 쓰지 않으며 Codex가 실행 중이어도 사용할 수 있습니다.

- ChatGPT 인증은 JWT의 발급자·사용자 ID와 선택한 계정/워크스페이스 ID를 비교합니다.
- API 키 인증은 키가 같은지 비교합니다. 이메일이 같다는 이유만으로 같은 계정으로 판단하지 않습니다.
- 식별 정보를 해석할 수 없는 형식은 JSON 내용이 동일한 저장본만 연결합니다.
- 같은 계정이 여러 이름에 저장되어 있으면 실제 인증과 일치하는 현재 선택 이름을 우선합니다.
  연결할 이름이 하나로 정해지지 않으면 임의로 선택하지 않습니다.

따라서 `codex login`을 직접 실행해 다른 저장 계정으로 로그인해도 실제 계정을 표시합니다.
미등록 계정이거나 구분할 수 없으면 그 상태를 표시하고 `save`로 등록하도록 안내합니다.
현재 `auth.json`이 없으면 로그아웃 상태입니다. 비교는 저장 파일 수에 비례하는 로컬 작업이며
추가 네트워크 요청을 보내지 않습니다.

**같은 계정으로 직접 재로그인한 경우와 자동 토큰 갱신은 파일만으로 구별하지 않습니다.**
두 경우 모두 같은 계정으로 처리하며, 이 도구를 거쳤는지 자체를 감사하는 기능은 제공하지 않습니다.

### 전환 전 자동 저장

`switch <이름>`은 대상 저장본을 읽은 뒤, 현재 인증에 대응하는 저장 이름을 확인합니다.
확인되면 현재 `auth.json`을 그 저장본에 덮어쓰고 선택한 인증을 적용합니다.
이는 해당 이름으로 `save --force`를 수행하는 효과이며 이메일에서 저장 이름을 새로 추정하지 않습니다.
현재와 같은 계정으로 전환하는 경우에도 갱신된 인증을 유지합니다.

현재 인증이 미등록이거나 저장 이름을 확정할 수 없으면 **전환을 중단**합니다.
먼저 `codex-auth save`로 등록하거나, 기존 저장본을 갱신하려는 의도라면 `codex-auth save --force`를 실행하세요.
직접 지정한 이름을 쓰려면 이 명령에 해당 이름을 함께 전달하면 됩니다.
자동 저장에 실패한 경우에도 현재 인증을 교체하지 않습니다.
현재 인증이 없는 로그아웃 상태에서는 자동 저장 없이 선택한 계정으로 전환합니다.

Codex는 사용 중 인증 토큰을 갱신할 수 있어 전환 직전 저장하면 오래된 토큰을 다시 적용하는 일을
줄일 수 있습니다. 다만 저장이 토큰의 유효성을 보장하거나 만료된 인증을 갱신하지는 않습니다.
인증에 실패하면 해당 계정으로 다시 로그인하고 저장하세요.
[OpenAI 인증 문서](https://learn.chatgpt.com/docs/auth).

### 로그아웃과 새 계정 로그인

`logout`은 `~/.codex/auth.json`과 현재 선택 표시를 지웁니다.
저장본 검색, 자동 저장, 확인 질문 없이 실행하므로 보관할 인증은 사용자가 먼저 `save` 해야 합니다.
`~/.auth/*.json`의 저장본은 유지하며, 이미 로그아웃 상태라면 그대로 성공합니다.
서버의 토큰을 폐기하는 기능은 아니며 로컬 인증 파일만 제거합니다.
이후 `codex login`으로 새 계정을 인증하고 `codex-auth save`로 등록할 수 있습니다.

### 프로세스 검사와 종료 범위

`switch <이름>`과 `logout`은 `/proc`에서 현재 Linux UID의 프로세스만 검사합니다.
다른 Linux 계정은 제외하며, 같은 UID라면 다른 `CODEX_HOME`에서 실행한 Codex도 검사합니다.
실행 파일 이름 `codex`, `codex-exec-server`, `codex-code-mode-host`, `codex-voice-host`를 기준으로
판별하며 app-server도 포함됩니다. 임의로 이름을 바꾼 실행 파일은 탐지하지 못할 수 있습니다.
셸 명령 문자열에 `codex`가 들어 있다는 이유만으로 종료 대상으로 잡지는 않습니다.

`status`는 PID, PPID, 상태, 종류, 터미널 유무만 출력합니다.
명령 인자, 환경변수, 프롬프트, 인증 토큰은 출력하지 않습니다.

`cleanup`은 대상에 SIGTERM을 보내고 최대 5초 기다립니다.
`--force`를 지정한 경우에만 남은 대상에 SIGKILL을 보내고 추가로 최대 3초 기다립니다.
프로세스 소유자와 실행 파일을 재확인하며, pidfd로 대상을 고정해 PID 재사용에 대비합니다.
여러 대상을 지정하면 전체 대상을 검증한 뒤 종료 요청을 시작합니다.
실행 주체를 확인할 수 없으면 종료를 중단하며, PID 1과 도구 자신은 종료하지 않습니다.

`cleanup all`의 범위는 명령 시작 시 확인한 같은 UID의 Codex 프로세스입니다.
좀비는 제외하고, 목록 확인 후 사라진 프로세스는 건너뜁니다.
종료 후 새로 시작되거나 자동 재시작된 Codex가 발견되면 오류와 목록을 출력합니다.
새 프로세스를 계속 추적해 종료하지는 않습니다. 서비스 관리자가 daemon을 재시작한다면
해당 서비스에서 먼저 중지하세요. 명령 성공 후에도 `switch <이름>`은 프로세스 검사를 다시 수행합니다.

상태 `Z`인 진짜 좀비는 이미 종료되어 계정 전환을 막지 않고, 종료 신호도 보내지 않습니다.
좀비 회수는 부모 프로세스의 역할이며 이 도구가 그 부모를 종료하지 않습니다.
대기 상태(`S`), 터미널 없음, PPID=1만으로 방치된 세션이라고 판단하지도 않습니다.

검사는 호스트의 일반 터미널에서 실행하세요. 컨테이너나 Codex 샌드박스의 `/proc`는
호스트 전체를 보여주지 않을 수 있습니다. 또한 검사 직후 다른 사용자가 새 Codex를 실행하는 것까지
막는 잠금 시스템은 아니므로 동시 실행을 하지 않는 전제는 유지됩니다.

### 파일 처리와 설정

- 보관 디렉터리는 권한 `700`, 복사한 인증 파일과 현재 선택 파일은 `600`으로 만듭니다.
- `save`도 `~/.auth`를 자동 생성합니다. 어디서나 실행할 명령 설치에는 `init`이 필요합니다.
- JSON 객체와 파일 크기를 검사하고 원본 바이트와 알 수 없는 필드를 그대로 보존합니다.
- 임시 파일 쓰기를 완료한 뒤 원자적으로 교체하므로 기존 파일을 먼저 비우지 않습니다.
- 인증 파일과 보관 디렉터리의 심볼릭 링크, 다른 소유자의 파일은 거부합니다.
- 토큰이나 전체 이메일을 출력하거나 네트워크로 보내지 않습니다.
- 설정, 대화 DB, 스킬, 플러그인을 수정하지 않습니다.

`CODEX_HOME`이 `~/.codex`와 다른 위치를 가리키면 인증 조회·저장·전환·로그아웃을 중단합니다.
일반 셸에서 `unset CODEX_HOME` 후 사용하세요. 별도 credential store를 설정했다면
`~/.codex/config.toml` 최상위에 `cli_auth_credentials_store = "file"`을 지정해야 합니다.
도구가 이 설정을 자동 변경하지는 않습니다.

`init`이 설치하는 명령은 소스 스크립트의 심볼릭 링크입니다.
프로젝트를 옮기면 기존 설치 링크를 제거하고 새 위치에서 `init`을 실행하세요.
이미 다른 파일이 설치 위치에 있으면 자동으로 덮어쓰지 않습니다.

### 테스트

프로젝트 디렉터리에서 실행합니다.

```bash
python3 -m unittest discover -s tests -v
```

임시 디렉터리, 가짜 JWT와 `/proc`, 신호 모의 객체로 실패 경로와 UID 격리를 검사합니다.
실제 pidfd 종료 테스트는 테스트가 생성한 일회용 `sleep` 자식에만 신호를 보냅니다.
실제 계정 인증이나 사용자의 Codex 세션은 변경하지 않습니다.
